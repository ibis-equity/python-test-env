ADF + Databricks + Delta Lake Demo

Retail Order Lakehouse Architecture for Batch, Streaming, Quality, and BI

Project overview

This repository demonstrates a modern data platform built around a medallion architecture. The goal is to ingest raw order data from multiple sources, validate it, transform it into curated analytical datasets, and expose trusted business metrics for reporting and operations.

The solution combines Azure Data Factory, Azure Data Lake Storage Gen2, Databricks, Delta Lake, Delta Live Tables, and Power BI into a practical enterprise-style flow.

Business use case

  • Capture customer orders from batch and streaming sources.
  • Normalize raw payloads into a consistent schema.
  • Reject invalid records through quality rules and quarantine them.
  • Provide curated silver and gold datasets for analytics and dashboarding.
  • Support monitoring, troubleshooting, and operational observability.

Core architecture

1. Ingestion

  • ADF orchestrates batch and stream ingestion workflows.
  • Landing files arrive in ADLS through landing/orders/batch and landing/orders/stream.
  • Databricks notebooks read raw files and write them to bronze Delta tables.
  • Streaming ingestion uses Auto Loader, checkpointing, and incremental processing.

2. Processing

  • Bronze captures minimally transformed raw records.
  • Silver applies cleaning, validation, deduplication, and business rules.
  • Gold exposes daily metrics and customer or product summaries.
  • PySpark and Spark SQL drive the transformations.

3. Consumption

  • Power BI imports curated datasets from Databricks SQL / analytical tables.
  • Dashboards display revenue, order count, quality rate, and data freshness.
  • Ops views track SLA compliance and failed-row volumes.
  • Monitoring queries help demonstrate production readiness.

Layered data model
  • Bronze: raw ingestion data retained at low transformation cost.
  • Silver: cleaned, validated, and enriched business-ready datasets.
  • Gold: aggregated marts for reporting and dashboard consumption.
  • Quarantine: invalid rows are separated for review and root-cause analysis.
Quality and validation approach
  • Required fields such as order_id, customer_id, order_ts, quantity, and unit_price are checked.
  • Quantity must be positive and whole-numbered.
  • Prices must be greater than zero and limited to two decimal places.
  • DLT expectations drop or quarantine rows that fail business validation.

ADF assets

The adf/ folder contains pipeline, dataset, and linked-service definitions for orchestration and data movement. These templates are designed to be adapted to a real Azure subscription and storage setup.

Databricks notebooks

The databricks/notebooks/ folder contains batch ingestion, streaming ingestion, silver transforms, and gold mart logic. These capture the actual operational flow of the demo.

DLT pipeline

The DLT pipeline in databricks/dlt/orders_dlt_pipeline.py centralizes quality expectations and emits a quarantine dataset for invalid rows that violate the business rules.

Python validation layer

The src/quality/rules.py module defines validation logic for order records. It validates field presence, timestamps, quantities, and pricing before records are considered acceptable.

Power BI artifacts

The powerbi/ folder contains SQL import queries, DAX measures, model design guidance, and report layout blueprints for business dashboarding.

Operational tooling

The ops/ and scripts/ folders include monitoring queries, runbooks, deployment helpers, and sample event emission scripts to support demonstration and sustainability.

1. Raw files land in ADLS

Sample batch and stream order payloads are placed in the landing folders. This simulates source ingestion from external systems or event producers.

2. Batch and streaming jobs ingest into the bronze layer

Databricks notebooks read the files and write records to Delta bronze tables, preserving the raw data and adding ingestion metadata.

3. DLT enforces expectations and quarantine logic

Rows are checked for validity before entering the silver layer. Failed rows are captured in a quarantine dataset for operational review.

4. Silver and gold tables create analytical products

Curated tables expose cleaned orders, daily sales summaries, and customer metrics. These are designed for reporting and downstream consumption.

5. Power BI delivers a business story

Dashboard visuals summarize revenue, order volume, quality pass rate, and freshness. This provides an executive summary and operations visibility.
